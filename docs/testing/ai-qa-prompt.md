## 3. 测试环境准备（含省钱策略）

### 3.1 图形验证码
登录接口在 `image_captcha_enabled=true` 时会校验图形验证码（`GET /api/auth/captcha` 取 id + 图片）。两种处理方式：
- **推荐**：请我临时关闭 → `UPDATE system_configs SET value='false'::jsonb WHERE key='image_captcha_enabled';`（即时生效，无需重启）；测完恢复为 `true`。
- 或者自行取验证码图片识别后提交。

### 3.2 上游成本控制（重要）
- 当前**所有** `new_api` / `openrouter` / `tokenhub` / `bigmodel` 线路的 `base_url` 都指向真实上游，**没有一条默认走 mock**。全局 `NEW_API_BASE_URL=http://mock-new-api:3002` 会被线路自身的 `base_url` 覆盖，所以别指望它。
- 要免费跑生成链路，请申请把**一条** `new_api` 线路临时改为 mock：
  ```sql
  -- 例：把 HL Image 2 的线路指向 mock（测完必须改回 https://hub.yardai.cc）
  UPDATE model_routes SET base_url='http://mock-new-api:3002'
  WHERE model_id=(SELECT id FROM models WHERE code='gpt-image-2');
  ```
- 未获批准前：**只测"预估/参数校验/列表/文档"这类不触发上游的路径**，不要点真实生成。对话类如必须测，优先选最便宜的模型并限定 1~2 次。
- 视频类（Seedance / Veo / Kling / Wan / Hailuo 等）单次成本最高，**默认不测真实生成**，只测参数面板与预估。

### 3.3 数据库查询模板
宿主 5432 被本机 Homebrew PG 占用，一律走容器：
```bash
docker exec -i docker-postgres-1 psql -U starai -d starai -c "<SQL>"

## 6. 测试方法要求

1. **黑盒优先**：界面操作用浏览器；接口用 HTTP 直接调（curl 或代码），便于构造边界值。
2. **每次都看三样东西**：浏览器 Console 报错、Network 中失败请求（4xx/5xx）、接口响应结构是否符合预期。**只截图不看控制台，等于没测。**
3. **数据一致性三方对照**：界面显示值 ↔ API 响应 ↔ 数据库实际值（尤其是余额、冻结、结算、任务状态）。
4. **异常与边界**：空字符串、超长文本、非法枚举、负数、超大数值、重复提交、快速连点、并发 5 个请求、上传超大文件/错误类型文件、任务进行中刷新页面/关闭标签页。
5. **失败注入**：用 `MOCK_FAILURE_RATE` 模拟上游失败，验证冻结是否退回、任务状态是否落到 failed、界面提示是否可读。
6. **权限矩阵**：未登录 / 普通用户 / 管理员；用户 A 访问用户 B 的 task、work、conversation。
7. **响应式**：1280 / 768 / 390 三档宽度；重点看侧边栏、芯片换行、表格横向溢出。
8. **性能粗测**：首屏时间、列表 100 条渲染、图片懒加载是否生效（可看 Network 里图片是否分批）。

```

前置条件：

实际结果：
证据：请求 ID / 失败请求的 URL 与状态码 / Console 报错原文 / 关键截图 / 相关 SQL 与结果
影响面：影响哪些用户、是否有资金或数据风险、是否可绕过
备注：是否已确认非缓存问题（请优先硬刷新/清 sessionStorage 后复测再提）

**严重级别定义**
- **P0 阻断**：无法登录/无法访问、资金错账、数据丢失或串号、越权可读写他人数据 → 立即停止其他测试，先报告。
- **P1 严重**：核心流程不可用（无法生成、无法结算、后台无法保存）。
- **P2 一般**：功能可用但有明显错误（文案错、状态不对、边界未处理）。
- **P3 建议**：体验与一致性问题。

## 8. 已知非缺陷（不要当 bug 报，也不要在这上面耗时间）

3. **TokenHub 线路密钥可能仍是占位符**：走 tokenhub 的模型可能报鉴权错误，属已知配置问题。
4. **`video_creation` 智能体的默认模型指向已停用的演示模型**（`image_fast_v1` / `video_demo_v1`）——执行失败属已知问题，记录一条即可，不必深挖。

7. **画廊 manifest 有 24 小时 sessionStorage 缓存**：改地址类问题复测前请先 `sessionStorage.clear()`，否则你会拿到旧数据误报。
8. **部分历史数据可能是空/异常**：这是未上线的开发库，只有 6 个用户、2 笔订单，不要把"数据少"当缺陷。
