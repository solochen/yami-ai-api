# Vidu S2-Avatar：实时版与离线（非实时）数字人调研

> 日期：2026-11-06　范围：Vidu Live / S2-Avatar　目的：确认当前「实时数字人对话」接的是哪个产品，并搞清「离线数字人」是干什么的、值不值得接。
> 一手来源：<https://platform.vidu.cn/vidu-stream/doc>（S2-Avatar 实时版 / 非实时版 / 组件版三套文档，页面为 JS 渲染，正文取自页面内嵌数据）。

## 一、结论速览

| | 实时版（当前接入） | 非实时版 / 离线版 |
| --- | --- | --- |
| 本质 | **通话**：RTC 音视频 + WebSocket 信令 + 内置 ASR/LLM/TTS | **生成**：一张图 + 一段音频/文字 → 异步产出一支说话视频 |
| 交互 | 能听、能答、能被打断、有静默小动作 | 无任何交互，剧本是死的 |
| 调用 | `POST /live/s_avatar/realtime`（文档现值）+ WS + AliRTC | `POST /ent/s_avatar/offline` + 轮询/回调 |
| 产出 | 实时流，关掉即消失 | MP4 文件 + 封面，可下载、可分发 |
| 单价 | 1.5 积分/秒 = **0.047 元/秒 ≈ 2.81 元/分钟** | 1 积分/秒 = **0.03125 元/秒 ≈ 1.88 元/分钟** |
| 计费口径 | 会话 `billed_seconds`（挂机/静默也在烧） | 产出视频 `duration`，向上取整到秒 |
| 60 秒成本 | ≈ 2.81 元，且只在这一次有效 | ≈ 1.88 元，播放 1 万次不再加钱 |
| 时延 | 准实时（秒级） | 40 秒 ~ 2 分钟出片 |

一句话：**离线数字人不是「便宜的实时数字人」，它是「数字人版的文生视频」**——你给它台词，它给你一支录像；它不认识用户，也接不住话。

## 二、当前项目接的确实是 Vidu S2-Avatar 实时版

代码证据（`services/api/internal/service/digital_human.go`）：

- `:502` `POST /live/v1/lives`，body 含 `call_mode`(audio/video)、`avatar.persona`、`avatar.image_uri`、`avatar.voice`、`llm.max_tokens`、`idle_timeout_seconds`、`knowledge_retrieval` —— 典型的 S2-Avatar 实时会话创建。
- `:485` video 模式传 `idle_action`；`:1054` 连 `wss://{host}/live/ws/live/connect?live_id=…&conn_id=…` 控制链路，`:1065` 发 `conn_init`，`:1165` 发 `hangup`。
- `:1019` 结束后用 `GET /live/v1/lives/{id}` 读 `billed_seconds` / `credits_cost` 结算。
- 前端 `apps/web/src/components/workbench/DigitalHumanWorkspace.tsx` 走 AliRTC 入会拉流。

成本折算也对得上官方价：`digital_human.go:29-34` 注释写的 1.5 积分/秒 × 0.03125 元/积分 = 2.8125 元/分钟，与官方产品页「每秒仅 0.047 元」一致。后台再按「平台销售佣金率」加价（`digitalHumanUserCharge`），默认 3% 佣金 → 用户侧 ≈ 2.90 元/分钟。

### 一个容易被忽略的点：文字模式不便宜

`:458-461` 里 `mode=="text"` 时 `viduMode` 仍然传 `audio`，也就是说**纯文字对话也在开一条完整的实时语音会话**（RTC + 内置 LLM），Vidu 按音频会话计每秒，和语音模式同价。文字模式省的是流量，不是钱。

## 三、离线数字人（非实时版）到底是什么

官方定义：*「非实时交互数字人（视频文件版）：输入一张角色图 + 一段音频（或说话文本），生成一段口型、动作对齐的说话视频。整个过程是异步任务制，不涉及 RTC、WebSocket 和实时链路。」*

### 接入方式

```
POST https://{host}/ent/s_avatar/offline
Authorization: Token vda_xxx

{
  "model": "vidu-s2",
  "image": "https://…/角色图.png",     // 必填，仅 1 张单人图
  "audio": "https://…/配音.mp3",       // 与 text 至少一个，都传时 audio 优先
  "text": "大家好，今天介绍一款产品",     // ≤ 10000 字，传了它系统自己合语音
  "voice": "female-shaonv",            // 仅 text 模式生效
  "timeline": "{\"actions\":[{\"text\":\"比个心\",\"time_range\":[2,10]}]}",
  "resolution": "720P",                // 720P(默认)/1080P/2K
  "callback_url": "https://…/callback"
}
```

- `timeline` 是**序列化后的 JSON 字符串**（要转义），用文字描述某段时间做什么动作；不传则由系统按音频自动生成动作。
- 查询：`GET /ent/v2/tasks/{task_id}/creations` → `state` ∈ `created/queueing/processing/success/failed`。
- 产出：`creations[].url`（无水印）/ `cover_url` / `watermarked_url`，**24 小时过期**，要转存。
- 耗时 40 秒 ~ 2 分钟；`progress` 会阶梯式爬升并长时间停在 99，**不能用它判断卡死**。
- 回调：`callback_url` + HMAC-SHA256（`secret_key` 就是 API Key），`success`/`failed` 最多投递 4 次。

### 计费

- **1 积分/秒 = 0.03125 元/秒**，按产出视频时长向上取整；`credits` 字段直接等于 `duration`。
- `text` 模式按合成语音估时（约 2~3 字/秒）计费。
- 创建接口只做余额预检不扣钱，进排队时才按预估时长预扣；失败或没产出则退还，最终以查询返回的 `credits` 为准。
- 余额低于 45 积分（约 1.4 元）就不能发起任务。

### 它能做什么 / 不能做什么

**能**：把一段稿子变成一支数字人口播视频，可控动作、可控分辨率、多语种音色、可批量、可无水印、产物可永久复用。

**不能**（关键）：
- 没有 ASR、VAD、LLM、打断、知识检索、长期记忆 —— 参数里连 `persona` 都没有；
- 不感知用户，用户问什么它都不变；
- 40 秒起步的时延，接不住任何对话；
- 单张单人图，多人 / 人脸不清晰 / 人体被遮挡直接失败（`MultiFaceDetected`、`ImageCheckFaceFailed` 等）。

## 四、成本结构差在哪

同样是 1 分钟内容：

| 场景 | 实时版 | 离线版 |
| --- | --- | --- |
| 1 分钟 | 2.81 元（一次性烧掉） | 1.88 元（得到一支片） |
| 100 人各聊 1 分钟 | 281 元 | 1.88 元（放同一支片） |
| 1 人聊 10 分钟 | 28.1 元 | 18.8 元（得到 10 分钟片，可复用） |
| 挂机 10 分钟不说话 | 照样 28.1 元 | 不存在这个概念 |

两个结论：
1. **单价比**：离线约为实时的 2/3（0.031 vs 0.047 元/秒）。
2. **真正拉开差距的是「按人按次」vs「按内容一次」**。实时版贵不是因为秒价高，而是因为它每来一个用户就重新计一遍费，且无法沉淀。

反过来说，实时版贵得有理：它把一个「会听、会想、会答、会动」的闭环打包了，你自己拼 ASR+LLM+TTS+驱动渲染只会更贵更慢。

## 五、离线数字人对应的产品场景

适合往当前项目里加的东西（都能复用现有 worker 异步任务链路，不用碰 RTC）：

1. **数字人口播短视频 / 带货素材**：一条脚本 → 一条成片，批量出，A/B 测不同开头。
2. **固定播报类内容**：公告、课程讲解、客服 FAQ、活动预告、门店介绍。
3. **多语言版本**：同一 script 换 `voice` 出多语种，不必重录。
4. **数字人 IP 资产**：一次生成，全平台分发，播放量再大也不加钱。
5. **预渲染高频答案**（见下）。

不适合：闲聊陪伴、答疑、需要看用户反应或被打断的任何场景。

## 六、建议：混合，而不是二选一

实时版真正的浪费在于「用 0.047 元/秒的价格去念一段永远不变的台词」。可以这么切：

- **高频、封闭的问题**（价格、营业时间、退换货规则、产品参数）→ 离线预渲染成短视频，用户问到直接播片段，成本接近 0；
- **开放式追问** → 才走实时版；
- 这样同一通 5 分钟通话，可能只有 1 分钟真的需要实时计费。

另一条路是 **组件版**（`POST /live/s_avatar/component`）：保留 Vidu 只做渲染，它给你的 RTC 频道推画面，你的 ASR/LLM/TTS 接管语音与对话，上行 PCM + type=9/10 文本 + type=7 打断。好处是模型线路、知识库、计费全在自己手里（现在走实时版，LLM 是 Vidu 内置的，你只能通过 `knowledge_retrieval` 回调塞资料）；代价是要自己扛实时语音链路的时延和成本。适合以后想要「自己的模型 + Vidu 的脸」时再切。

## 七、要核实 / 注意的点

1. **创建接口版本**：代码用 `POST /live/v1/lives`，而当前官方文档的实时版创建入口是 `POST /live/s_avatar/realtime`（查询/列表仍是 `/live/v1/lives`）。现在能跑说明旧入口还兼容，但旧入口大概率拿不到新能力（`idle_motion`、`memory_retrieval`、`rtc.provider` 换 TRTC/Agora 等），值得排期核对一次。
2. **分辨率是否加价**：离线文档写「每秒 1 积分」且 `credits == duration`，字面看 2K 与 720P 同价，这点建议实测确认（同类产品通常按分辨率分档）。
3. **离线不做内容审核的兜底**：`AuditSubmitIllegal` / `CreationPolicyViolation` 会直接失败，需要前端给出可读提示并允许换素材重试。
4. **产物 24 小时过期**：必须转存到自己的对象存储，不能把 Vidu 的 URL 直接落库对外。
5. **前端展示两处小问题**（`DigitalHumanWorkspace.tsx`）：
   - `:597` 把「元/分钟」的价格标签写成了「算力/分钟」，而后端返回的是 `vidu_*_price_per_minute`（元），量级容易被误读；
   - `:531` 预估费用固定用 `prices.video` 乘时长，纯语音/文字通话也会按视频价预估，`voice`/`video` 两个价配得不一样时预估会偏高。

### 8.3 关键结论：你在为「画面」付费，不是为「对话」

把数字人拆成两层看：

- **语音对话层**（RTC + ASR + TTS + LLM）：市场价 0.1 ~ 0.2 元/分钟，已经很便宜；
- **视频渲染 + 口型驱动层**：这才是价格鸿沟所在，从 0.06（端渲染）到 2.8（Vidu 打包）差 47 倍。

Vidu 的 2.81 元里，约九成付给了「实时出画面」。所以降本只有三条路，且互不冲突：

1. **非实时化**：高频内容离线预渲染（见本文件第四、六节）；
2. **拆开买**：语音用 0.1 元/分钟的通用方案，画面单独找供应商（⚠️ 阿里云数字人已退市，可选的画面供应商变少了，见 8.2.1）；
3. **自建渲染**：量大以后的终局，但不是省钱的开始，是换了一种花钱方式。

**这不是「按原价 99 计算」能解释的**：定价页的容量估算与支付金额无关，只取决于费率。

- 若按 60 积分/分钟：3154 ÷ 60 = 52.57 ≈ 53 分钟 ✅（卡片口径）
- 若按 90 积分/分钟：3154 ÷ 90 = 35.04 分钟

反过来，同一张卡片的「预计可生成 6 分钟 540p 视频」是**算对了**的：Q4 Preview 540p = 9 积分/秒（官方价目表），3154 ÷ 9 = 350 秒 = 5.84 分钟 ≈ 6 分钟 ✅。这说明整张卡片是逐条按官方费率表计算的，唯独数字人那条用了 1 积分/秒 —— 高度符合「S2 将实时版从 1 提到 1.5 之后，营销文案未同步」的判断（1 积分/秒正是 S1 时代实时版的费率）。

**⚠️ 抵扣范围待确认**：控制台「资源包管理」有「抵扣类型 / 功能类型」两个字段，套餐卡片只列了「视频、音频、图像、解决方案」，没有明写「数字人」。下单前应确认套餐积分能否抵扣实时数字人，最省事的办法是先买 69 元包实测一通 5 分钟通话。

### 8.6 国内产品要额外考虑的事

价格之外，Vidu 的真实优势是：境内合规、中文人设与知识库回调、已有可用集成、中文场景的效果调优。换成 HeyGen 这类境外服务，会引入美元结算、跨境延迟、数据出境合规（境内 to C 产品基本过不了）。

所以对比不能只看单价，要按「合规 + 产品生命周期」先过滤一遍。过滤结果是：

| 路径 | 状态 |
| --- | --- |
| Vidu（现状） | ✅ 可用，2.81 元/分钟（7 折套餐 1.97） |
| 阿里云虚拟数字人 | ❌ 已退市，2026-11-30 停止新购 |
| HeyGen LiveAvatar | ⚠️ 便宜 2~4 倍，但境外合规过不了 |
| 阿里云云市场（蚂蚁灵境/相芯/一知智能） | ❓ 待询价，第三方商品 |
| 自建开源 + 语音外购 | ✅ 唯一可自主可控的长期降本路径 |

**结论修正**：剔除阿里云之后，短期内「换供应商降本」这条路基本走不通——剩下的只有自建。因此在当前阶段，性价比最高的动作不是换供应商，而是**把计费口径改对（7 折）+ 把高频内容非实时化**。
