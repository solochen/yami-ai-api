## 5. 默认角色

角色架新增「默认角色 / 我的角色」两个 tab。默认角色共 10 张，全部为白底、单人、正面半身，适合直接做换角测试：

| 分类 | 角色 |
| --- | --- |
| 型男 | 顾言、亚历克斯 |
| 美女 | 苏晚、艾琳 |
| 动物 | 橘座（猫）、金豆（金毛） |
| 卡通 | 阿蓝（3D）、小满（二次元） |
| 古风 | 昭华（盛唐）、苏念（江南） |

实现方式：

- 图片保存在 `apps/web/public/character-studio/defaults/`，是静态资源，不依赖任何用户素材；
- 第一次点击某张默认角色时，前端把图片上传到当前用户的素材库，自动创建同名角色卡并选中；之后点击同一张会直接选中，不重复创建；
- 直播中点击默认角色会走和普通角色卡一样的热切换；
- 默认图由 Vidu `viduq2` 图片模型生成，8 积分/张，10 张共 80 积分；本地 develop 的项目模型网关是 mock，只能返回 64×64 色块，因此没有用项目里的 C Dance/GPT-image 配置；
- 动物/卡通角色的实际换角效果受上游主体识别限制，页面已加提示；
- 本地素材地址仍是 `/media/...`，和手动上传一样需要公网存储域名；生产 COS 环境正常。
- 静态图本身由 web 站点提供，不需要先放进 COS；真实开播拉取的是点击后复制到用户素材库的副本。生产首次点击会自动把副本上传到 COS，返回 `https://img...` 绝对地址；如果服务端仍返回 `/media/...`，检查 `MINIO_PUBLIC_URL` / `storage_public_url`。

## 6. 公网参考图与生产存储

**本地为什么会报「角色参考图需要公网可访问的地址」**

本地 `MINIO_PUBLIC_URL=/media`，上传接口返回 `/media/...` 相对地址；上游渲染服务在公网，访问不到 `localhost`，所以开播时被拒绝。这不是生产必然出现的问题。

**生产怎么做才会通**

1. `MINIO_PUBLIC_URL`（或后台 `storage_public_url`）配置为**绝对公网域名**，例如 `https://img.yourdomain.com`；上传返回 `https://img.yourdomain.com/<key>`。
2. 该地址在无 Cookie、无登录的浏览器/命令行里能直接 `200`；COS 私有桶要确认 CDN 回源可公开读取。
3. 不要用短期签名 URL（开播时可能已过期），不要开拦截非浏览器 UA/防盗链的规则。
4. 如果上传仍是相对地址，可在「实时数字人」配置 `vidu_public_base_url` 补全，但它也必须是公网可达的源站。

**现在页面提供的两种角色图来源**

- 本地上传：进入素材库，适合生产 COS/CDN 已配好的情况。
- 公网链接：直接粘贴 `https://...`，编辑器内实时预览；适合本地联调、外部 CDN 素材，以及素材不在本站素材库的情况。

本地用公网链接保存角色卡后，启动会越过图片校验；当前因为 `vidu_api_key` 仍是占位值，会停在「凭证无效」，属于预期。
